# CLI

```bash
npx next-smart-router generate [options]
```

Walks a Next.js `app/` directory and writes a route manifest.

## Options

| Flag                           | Default                | What it does                                                                              |
| ------------------------------ | ---------------------- | ----------------------------------------------------------------------------------------- |
| `--app-dir <path>`             | `./app`                | Root of the app directory                                                                 |
| `--out, -o <path>`             | `./route-manifest.ts`  | Output. `.json` emits JSON, anything else a TS module                                     |
| `--page-extensions <list>`     | `tsx,ts,jsx,js,mdx,md` | Mirrors `pageExtensions` from `next.config`                                               |
| `--ignore <list>`              | —                      | Comma-separated directory names to skip                                                   |
| `--watch, -w`                  | —                      | Regenerate on change (debounced 100ms)                                                    |
| `--check`                      | —                      | Exit non-zero if the manifest is stale or conflicted; also warns about unreachable routes |
| `--no-types`                   | —                      | Skip the `Route` union                                                                    |
| `--no-meta`                    | —                      | Skip `route.meta.json` sidecars                                                           |
| `--silent`                     | —                      | Suppress output                                                                           |
| `-h, --help` / `-v, --version` | —                      |                                                                                           |

## What it includes and skips

| Directory                    | Result                                                               |
| ---------------------------- | -------------------------------------------------------------------- |
| `about/page.tsx`             | `/about`                                                             |
| `(marketing)/about/page.tsx` | `/about` — route groups add no segment                               |
| `w/[id]/page.tsx`            | `/w/[id]`                                                            |
| `docs/[...slug]/page.tsx`    | `/docs/[...slug]`                                                    |
| `files/[[...path]]/page.tsx` | `/files/[[...path]]`                                                 |
| `_internal/page.tsx`         | skipped — private folder                                             |
| `w/[id]/@modal/page.tsx`     | skipped — parallel route slot                                        |
| `feed/(..)photo/page.tsx`    | skipped — intercepting route, renders an existing URL                |
| `api/users/route.ts`         | skipped — route handler, serves no page                              |
| `settings/api/page.tsx`      | **`/settings/api`** — a page in a folder named `api` is still a page |

That last row is the distinction that matters: handlers are detected by the
presence of `route.ts`, not by folder name.

## Output

```ts
/* AUTO-GENERATED by next-smart-router — DO NOT EDIT */

export const ROUTES = new Set(["/", "/w", "/w/[id]", "/docs/[...slug]"]);

export type Route = "/" | "/w" | "/w/[id]" | "/docs/[...slug]";

export const META = {
  "/w/[id]/settings": { title: "Settings", requiresAuth: true },
} as const;
```

Routes are emitted in **specificity order**, which is the order matchers use.

`META` is collected from `route.meta.json` files sitting next to a `page`:

```json
// app/w/[id]/settings/route.meta.json
{ "title": "Settings", "icon": "cog", "requiresAuth": true, "roles": ["admin"] }
```

It feeds breadcrumb labels, `useChildren` menu titles, and middleware
protection.

## Only writes when something changed

`generate` compares the serialized output against the file on disk and skips
the write if they match. That is what makes `--watch` safe to point at a
directory Next is also watching — the generator can't touch a file inside the
project, trigger a recompile, and run again.

## `--check` in CI

```yaml
- run: npx next-smart-router generate --check
```

Fails when the manifest was out of date (it rewrites it, so the diff is right
there) or when validation found an error: a catch-all that isn't the final
segment, two folders that resolve to the same URL path, or a page and a route
handler in the same folder.

### Two folders, one path

Route groups add no path segment, so `(marketing)/about` and `(app)/about` both
serve `/about`. Next refuses to build that, and the error names the folders:

```
✗ 2 folders resolve to "/about" ((app)/about, (marketing)/about) — Next cannot
  build two pages at the same path
```

This is an error, not a warning: the app already cannot build, and finding out
from `--check` is faster than finding out from `next build`.

### A page and a route handler in one folder

A folder holding both `page.tsx` and `route.ts` is also a Next build error. The
route is left out of the manifest, and `--check` fails naming the folder:

```
✗ "/settings" (settings) has both a page and a route handler — Next cannot
  build a page and a route.ts at the same path
```

A folder holding only `route.ts` is an API endpoint, not a page, and is skipped
without comment.

### Warnings that do not fail the build

`--check` also reports two things without changing the exit code:

**Unreachable routes.** A pattern a more specific sibling shadows at every depth
it could serve, so no URL reaches it. The page file exists, so nothing else
catches this:

```
⚠ 1 route unreachable by any URL that this manifest models:
    /docs/[...slug] — "/__nsr0/__nsr1" resolves to /docs/[a]/[b]
  Rewrites in next.config and middleware are NOT modeled, so a route
  reached only through a rewrite will appear here. Check before deleting.
```

**A route set Next itself rejects.** `--check` asks Next's own route sorter
whether it would accept the set, so a `next build` failure surfaces in seconds
instead of minutes:

```
✗ Next rejects this route set, so "next build" will fail:
    You cannot use different slug names for the same dynamic path ('id' !== 'slug').
```

That probe reads an internal Next module resolved from your project. If it
cannot be loaded, `--check` says so in one line and carries on:

```
  (skipped Next's own route validation — next/dist/shared/lib/router/utils/sorted-routes not loadable here)
```

Neither warning affects the exit code. Unreachable detection has not been
validated against apps that rewrite, so failing a build on it would be a
promise this cannot keep yet. Use `findUnreachableRoutes` directly if you want
to gate on it in your own check.

## Watch mode

```bash
$ next-smart-router generate --watch
✅ next-smart-router: 24 routes → route-manifest.ts
👀 next-smart-router: watching app
✅ next-smart-router: 25 routes → route-manifest.ts
```

Uses recursive `fs.watch` where available (Windows, macOS, Linux on Node 20+)
and falls back to polling otherwise.

## The plugin

Prefer this over wiring scripts:

```js
// next.config.mjs
import { withSmartRouter } from "next-smart-router/plugin";

export default withSmartRouter(
  { reactStrictMode: true },
  { out: "src/route-manifest.ts" }
);
```

It detects `app/` or `src/app/`, reads `pageExtensions` from the config it
wraps, generates on build, and watches on dev.

## Programmatic use

```ts
import { collectRoutes, generateRoutes } from "next-smart-router/cli";

const { routes, meta } = collectRoutes("./app");
const result = generateRoutes({ appDir: "./app", out: "./manifest.ts", log: false });

result.changed; // false when the file was already correct
result.conflicts; // validation findings
```

`generateRoutes` takes `GenerateRoutesOptions`:

| Option           | Default                   | Notes                      |
| ---------------- | ------------------------- | -------------------------- |
| `appDir`         | `<cwd>/app`               |                            |
| `out`            | `<cwd>/route-manifest.ts` | Extension picks the format |
| `log`            | `true`                    | Also prints conflicts      |
| `pageExtensions` | `tsx,ts,jsx,js,mdx,md`    |                            |
| `emitTypes`      | `true`                    | The `Route` union          |
| `emitMeta`       | `true`                    | `route.meta.json` sidecars |
| `ignore`         | `[]`                      | Directory names to skip    |

It returns `GenerateResult`: `{ routes, meta, conflicts, changed, out }`.

`collectRoutes(appDir, options)` accepts the `pageExtensions`, `emitMeta` and
`ignore` subset and returns `{ routes, meta, sources, clashes }` without writing
anything. `sources` maps each route to the folders that produced it; `clashes`
lists the folders holding both a page and a route handler, as `FoundRoute`
(`{ route, dir }`) entries.

### `watchRoutes(options)`

The watcher behind `--watch`, if you'd rather drive it yourself. Takes
`GenerateRoutesOptions` plus an `onGenerate(routes, changed)` callback, and
returns a function that stops watching.

```ts
import { watchRoutes } from "next-smart-router/cli";

const stop = watchRoutes({
  appDir: "./app",
  out: "./route-manifest.ts",
  log: false,
  onGenerate: (routes, changed) => {
    if (changed) console.log(`${routes.length} routes`);
  },
});

process.on("SIGINT", stop);
```

It generates once immediately, then debounces file events by 100ms.
