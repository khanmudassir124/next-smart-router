# Getting started

## Install

```bash
npm install next-smart-router
```

`next` and `react` are optional peer dependencies. The core entry
(`next-smart-router`) needs neither — it is pure functions over strings, so it
works in Server Components, Route Handlers, `middleware.ts`, tests and Node
scripts. The hooks and components live in `next-smart-router/react`.

## 1. Generate a route manifest

The library needs to know which routes exist. The generator reads that from
your `app/` directory.

### With the plugin (recommended)

```js
// next.config.mjs
import { withSmartRouter } from "next-smart-router/plugin";

export default withSmartRouter({
  reactStrictMode: true,
});
```

It generates on `next build` and watches during `next dev`, and reads
`pageExtensions` from the config it wraps. The file is only written when its
contents change, so it cannot cause a rebuild loop.

### With the CLI

```bash
npx next-smart-router generate --app-dir src/app --out src/route-manifest.ts
```

Add it to your scripts:

```json
{
  "scripts": {
    "dev": "next-smart-router generate --watch & next dev",
    "prebuild": "next-smart-router generate"
  }
}
```

The generated file looks like this:

```ts
/* AUTO-GENERATED by next-smart-router — DO NOT EDIT */

export const ROUTES = new Set(["/", "/w", "/w/[id]", "/docs/[...slug]"]);

export type Route = "/" | "/w" | "/w/[id]" | "/docs/[...slug]";

export const META = {
  "/w/[id]/settings": { title: "Settings", requiresAuth: true },
} as const;
```

Whether you commit it is a choice. Committing means `tsc` works on a fresh
clone; leaving it generated means no derived file in git, but CI has to run the
generator before typechecking. Either way, add `--check` to CI so a stale
manifest fails the build rather than shipping.

## 2. Initialize

```ts
import { initializeSmartRouter } from "next-smart-router";
import { ROUTES, META } from "@/route-manifest";

initializeSmartRouter({
  routes: ROUTES,
  meta: META,
});
```

**Where does this go?** Next builds the server and the client as separate module
graphs, so this runs once per graph. Put it in a module _both_ graphs import —
a small setup file imported from your root layout is the reliable choice:

```tsx
// components/smart-router-setup.tsx
"use client";
import { initializeSmartRouter } from "next-smart-router";
import { ROUTES } from "@/route-manifest";

initializeSmartRouter({ routes: ROUTES, force: true });

export function SmartRouterSetup() {
  return null;
}
```

```tsx
// app/layout.tsx
import { SmartRouterSetup } from "@/components/smart-router-setup";

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <SmartRouterSetup />
        {children}
      </body>
    </html>
  );
}
```

If a matcher runs before initialization, the registry holds only `"/"` — the
library warns once in development rather than quietly returning wrong answers.

For anything where a global is the wrong shape (middleware, tests, two route
sets in one process), use [`createRouter`](./concepts.md#createrouter) instead.

## 3. Turn on typed routes

```ts
// smart-router.d.ts
import type { Route } from "@/route-manifest";

declare module "next-smart-router" {
  interface Register {
    route: Route;
  }
}
```

From here on:

```ts
buildHref("/w/[id]", { id: 42 }); // ✓
buildHref("/w/[typo]", { id: 42 }); // ✗ not assignable to Route
getParams("/w/[id]").id; // ^? string
```

Skip this and everything still works — `Route` is just `string` until it's
registered.

## 4. Navigate

```tsx
"use client";
import { useSmartRouter, SmartLink } from "next-smart-router/react";

export function WorkspaceActions() {
  const nav = useSmartRouter();

  return (
    <>
      <SmartLink href="../members" activeClassName="is-active">
        Members
      </SmartLink>

      <button onClick={() => nav.push("./settings")}>Settings</button>
      <button onClick={() => nav.fsBack()}>Back</button>
    </>
  );
}
```

`nav.fsBack()` walks up the path to the nearest route that actually exists, so
it never lands on a 404 — unlike browser back, which returns wherever the user
came from.
